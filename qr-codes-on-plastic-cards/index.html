Plastic Card Notes

Printing QR codes on plastic cards: size, contrast, quiet zone and finish

A QR code that looks sharp on a laptop often fails once it is a few centimetres across on a plastic card. The file is rarely invalid. What usually fails is the physical print: modules too small, the quiet zone cropped, contrast too low, or gloss throwing a reflection at the camera.

ISO/IEC 18004, the QR Code symbology specification, defines the pattern in modules, not as one millimetre size for every card. Plastic cards make that translation tight: a small face, shop lighting, a phone in one hand, and a finish that is part of the optical path.

Size is a module problem, not a fixed millimetre rule

A QR Code is a square grid of modules — the smallest black or white squares in the symbol. Version 1 is 21 × 21 modules. Each later version adds four modules on a side, up to version 40 at 177 × 177. A short web address can sit in a low version. A long campaign URL with tracking parameters forces a higher version, packing more modules into the same space.

The millimetre size is the module width times the number of modules, plus the quiet zone. DENSO WAVE, which developed QR Code, recommends printing the symbol as large as the layout allows, with enough printer dots that module edges stay distinct. There is no honest universal minimum in millimetres, because the printer, the finish and the scanner all matter.

Shrink a dense code into a tight corner and the modules become a grey texture instead of a grid. Keep the encoded text short so each module can be larger. When you reserve a box in the artwork, include the quiet zone, not just the modules. The overall footprint is (modules + 8) times the module width, because of a four-module margin on every side. A code that decodes easily at 40 mm on a monitor can fail at 15 mm on a finished card, especially under gloss.

The quiet zone is four modules, and it is not optional

ISO/IEC 18004 requires a quiet zone of at least four modules on all four sides. That margin must be the light background colour, free of type, logos, rules, photographs and the card edge. Cutting it is one of the most common reasons a printed code will not scan.

Designers often draw a neat square around the black modules and drop it into a coloured panel. If that square omits the four-module margin, or a crop, frame or trimmed edge later eats into it, the finder patterns no longer sit in clear space and many cameras cannot lock on. Less than four modules is a defect, not a clever use of space.

Error correction helps, but it is not a licence to damage the code

QR Code uses Reed-Solomon error correction at four levels, written in ISO/IEC 18004 as L, M, Q and H. In approximate terms they can recover about 7, 15, 25 and 30 per cent of the codewords if part of the symbol is damaged or obscured. A higher level helps on a handled card, or with a small centre logo, but it is not a substitute for contrast, size or a proper quiet zone. For the same payload, a higher level also needs more modules, so the symbol grows — or the modules shrink if the artwork box stays fixed.

For a clean, dark-on-light code with no logo, level M is a reasonable default. Use Q or H if the card will be scratched, the finish is optically awkward, or a logo will cover part of the grid. Keep any logo small, and never cover the three finder patterns in the corners, the timing patterns, or the alignment pattern on version 2 and above.

Contrast: dark modules on a light background

The symbol is specified as dark modules on a light background, which is what most cameras and dedicated scanners expect. Light-on-dark or low-contrast brand-colour treatments look tidy in a mock-up and then fail at the counter. Aim for a near-black code on a near-white field. Photographs, mid greys and metallic-effect or foiled areas behind the modules all reduce contrast or reflect light unevenly. On clear or frosted plastic the card is not an opaque white substrate, so the code needs a solid light backing — often a white support behind that part of the design.

A red or orange code on white may be invisible to a scanner that uses red illumination, even if a phone camera can see it. If staff will use a dedicated reader, do not assume a phone test is enough. If the holder will scan on a phone, still keep the luminance contrast high, and do not rely on inverted colours unless you have tested the actual apps people will use.

Gloss, matte and the way light hits a card

Gloss gives a brighter, more reflective surface. Matte is lower-sheen. A glossy card under a downlight, a window or a phone torch can throw a highlight straight across the modules, so the camera briefly sees a white smear instead of a grid. A well-sized, high-contrast code on gloss will often still scan if the card is tilted, but it is slower, and some attempts fail. Matte usually makes that easier. If the design calls for gloss, give the code enough size, keep the contrast high, and test under the lighting you actually have in the shop or at the desk. Do not print it over a window, a metallic ink, or a busy photograph.

Static codes, dynamic codes, and unique codes on every card

A static QR code contains the payload itself: a web address, contact details, a Wi-Fi string, and so on. Once it is printed, that payload does not change. If the code holds a URL, you can still update the page at that address. You cannot make the same printed pattern point somewhere else.

What marketing tools often call a dynamic code is usually a short URL that redirects. The redirect can be edited later, and the service may offer scan counts. The trade-off is dependence on that service. If the subscription lapses or the short link is retired, a wallet full of cards can stop resolving.

If every card should open a different page or carry a different identifier, that is variable data. Supply the unique content in a spreadsheet, one row per card, and have the codes produced with the print run so each pattern matches the right record.

A generator is useful when the same static code appears on every card — a join page, a menu, a support URL. We built a QR code generator for that job: it runs in the browser, lets you set the printed size and quiet-zone margin, and runs a software decode before you download the file. That check is not a substitute for scanning a printed sample at final size, on the finish you will actually use.

Test the finished card, not only the file

Before a full run, print a sample at the final millimetre size, on a similar finish, and scan it with the phones or readers that will be used in practice, under overhead lighting and at a natural holding distance. If it is slow or unreliable, encode less data, enlarge the modules, restore the quiet zone, increase contrast, or move off a reflective or transparent area.
