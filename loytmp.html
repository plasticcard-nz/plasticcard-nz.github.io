Barcode, magnetic stripe, QR or NFC? Choosing the data layer for loyalty and membership cards

A loyalty or membership card has two jobs. One is visible: the brand, the member's name, a number a person can read. The other is the data layer — the thing a till, a door reader or a phone uses to find the right record. Reprints often happen when that layer is chosen because it looked modern, not because it matched the hardware on the counter.

The card almost never stores the balance or the entitlements. Those live in your programme software. The data layer is usually just a reliable identifier, so compare the options on cost, readers, POS compatibility, durability, security, and how you supply a different value on every card. Cost

A printed linear barcode or QR code is usually the least expensive data layer to add. It is ink in a reserved area of the artwork, with no stripe, chip or inlay. A magnetic stripe adds a physical component and, if needed, an encoding step — more than a printed code, but still simple when the terminals already swipe cards.

NFC or other RFID is typically the most expensive physical option, because each card needs a chip and antenna inlay, and the identifier has to be programmed to the provider's specification. Visually identical cards can use different chips and frequencies. The card is only part of the cost: a cheap barcode is a false economy if every location then needs a new scanner.

Readers

  • A linear barcode needs a barcode scanner, or a camera and software that can decode that symbology into the POS.
  • A QR code needs a 2D imager or a phone camera. A conventional one-dimensional laser scanner will not read it.
  • A magnetic stripe needs a swipe reader set up for the correct stripe type and data.
  • NFC and other contactless credentials need a reader that supports the exact chip, frequency and protocol.

Phones help in one case and mislead in another. Many customers can scan a QR code without extra hardware. Some NFC tags can be read by a compatible smartphone, but a door-access RFID card is not automatically readable by a phone. A payment terminal that accepts contactless bank cards will not normally read a loyalty or membership chip unless it has been set up for that. Check every location, not only head office.

POS and system compatibility

For a staffed retail or hospitality counter, a linear barcode remains a widely supported option on existing POS and loyalty systems. Common symbologies include Code 128, Code 39 and EAN-13, and they are not interchangeable: EAN-13 is a fixed-length retail identifier, while Code 128 can hold a longer, more flexible string. The provider should name the symbology, the exact data format, and any prefix or number range. QR codes fit when the cardholder does the scanning — to register, check a balance, or open a member page — or when the till already uses a 2D imager or a tablet camera. They are a poor sole identifier if some locations still have only a 1D laser scanner.

Magnetic stripes belong where the hardware is already a swipe reader: some POS and gift-card terminals, and many hotel locks. ISO/IEC 7811 specifies the recording technique, including low-coercivity stripes (ISO/IEC 7811-2) and high-coercivity stripes (ISO/IEC 7811-6). High-coercivity media are specified for improved resistance to accidental erasure; low-coercivity media can be encoded with a weaker field, which some rewrite-heavy systems prefer. ISO/IEC 7813 specifies the data structure used on financial transaction cards. A loyalty or membership card may use a 7811-compliant stripe with a provider-set data format; it is not automatically a financial-transaction card, so do not copy a bank-card track layout unless that is what the system requires. Track capacities, including framing characters, are 79 alphanumeric on Track 1, 40 numeric on Track 2, and 107 numeric on Track 3; the provider should say which tracks to encode and with what data.

NFC, for a close tap on a phone or a proximity reader, is built around ISO/IEC 14443. That standard covers proximity cards operating at 13.56 MHz, with Type A and Type B signalling, typically read within about 10 cm of the reader. Not every RFID card is a 14443 NFC card. Older low-frequency access cards, and ISO/IEC 15693 vicinity cards, use different protocols and ranges. Confirm the chip, frequency, encoding and a test method with the provider before artwork is approved.

Durability

A printed barcode or QR code lives on the surface. It can be scratched, worn at the till, or made harder to read by dirt and fading.

A magnetic stripe wears with swiping and can be erased by a magnet or by contact with another striped card in a wallet. High-coercivity stripes resist accidental erasure better than low-coercivity ones; they are not immune to wear, and coercivity is not a measure of how many times a stripe can be rewritten. An NFC or RFID inlay sits inside the card, which helps against abrasion, but the card can still crack, and holes, slots, embossing, severe bending or some metallic finishes can damage the antenna. In all four cases, a visible number printed large enough to type is a useful fallback when the machine-readable layer fails.

Security

A printed number, a barcode and a QR code are all visible. Anyone who can photograph the card can copy the identifier. A magnetic stripe is not visible, but it can be read and written with readily available hardware; it should not be treated as a security feature. A simple NFC tag that only stores a URL or a unique ID can often be cloned.

For most loyalty and membership programmes, treat the card as a bearer identifier, not as the security system. Access rights, balances and personal data belong on the server, behind the login, PIN or staff process you already trust. Do not put sensitive personal information into a barcode or a QR code.

Variable data belongs in a spreadsheet

If every card carries a different number, barcode, QR payload or encoded stripe, that is variable data. Supply it as a spreadsheet with one row per card and a clearly labelled column for each field: name, member or customer number, expiry date, the barcode or QR content, and any stripe data. Generate every representation of the identifier from the same approved source record; do not retype it between the face, the barcode and the stripe. Preserve leading zeros, check for duplicates and gaps, and decide who approves the final list.

Choosing, and when to combine

There is no single best data layer. A small staffed loyalty scheme may only need a printed number and a barcode the till already scans. A programme that wants members to open a page on their phone can add a QR code without abandoning the barcode at the counter. Specify a magnetic stripe where swipe hardware already exists, and stay with ISO/IEC 14443 if that is what an existing gym or access system issues. Combinations often suit a mixed network, but only if each method holds the same identifier, the layout leaves room for all of them, and a short sample is tested on the real hardware in more than one location before the full run.
